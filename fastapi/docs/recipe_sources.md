# 레시피 데이터 확장 조사 — 2026-10-23

## 결론과 현재 경계

식품안전나라 한 공급자만으로 국내 조리법의 다양성을 충족한다고 보지 않는다. 파싱 보완과 신규 공급자 확보는 서로 다른 작업이다. 이번에는 기존 1,156건 중 구조 검증 통과를 792건에서 870건으로 늘렸다. 다른 공급자의 레시피를 DB에 넣거나 신규 연동을 활성화하지는 않았다.

수만 건의 **재료·조리 단계·이미지·저장/가공/서비스 제공 권한**이 모두 충족되는 무료 원천은 이번 조사에서 확정하지 못했다. 공개 레시피 수, 무료 다운로드 수, 우리 서비스에서 재배포할 수 있는 레시피 수를 같은 지표로 보고하지 않는다.

샘플 총 건수는 전체 수집 완료 수나 식품안전나라와 중복 제거한 추가 수가 아니다. 전체 수집용 키는 별도 신청해야 하며 식품안전나라 키를 재사용하지 않는다. sample 키로 전체 데이터를 우회 수집하지 않는다.

공식 요청 주소는 `http://211.237.50.150:7080/openapi/…`이다. 이번에는 공개 샘플만 호출했다. 실제 키를 평문 HTTP로 전송하기 전에 HTTPS 제공 여부나 포털 파일 제공 경로를 확인한다. HTTPS 지원 여부는 아직 확인하지 못했다.

공공데이터포털의 이용허락범위 표시와 제공기관 포털의 과거 저작권표시·동일조건변경허락 표시, 현재 일부 항목의 빈 표시가 일치하지 않는다. 원문·이미지 저장과 가공 사본 제공은 적용할 최신 조건 확인 후 승인한다.

다음 구현은 세 테이블 전체 수집 → RECIPE_ID 결합 → IRDNT_CPCTY 분량 파싱 → IRDNT_SN/COOKING_NO 순서 검증이다. QNT 인분은 명시된 경우에만 변환하며, 누락된 재료·단계는 생성하지 않는다.

## 2. KADX 만개의레시피 무료 데이터 상품

- [KADX 공식 플랫폼](https://kadx.co.kr/)
- [무료 레시피 데이터 상품](https://kadx.co.kr/opmk/frn/pmumkproductDetail/PMU_b72356bd-458a-4734-ba2e-f21de4167b0a/5)

공식 플랫폼과 활용사례에서 무료 상품 존재를 확인했다. 대량 한국어 레시피 확보를 위한 우선 조사 후보이다. 상품 상세의 동적 데이터·현재 사용 조건은 충분히 읽지 못했고 CSV도 다운로드하지 않았다. 실제 파일의 행 수·컬럼·조리 단계 유무는 미확정이다.

외부 목록의 18개 컬럼 설명만으로 조리법 전문을 포함한다고 판단하지 않는다. 버전별 상품 ID·취득일·이용 조건을 확인해야 하며 무료/교육용이라는 이유만으로 변경·상업적 이용·API 재제공이 허용된다고 해석하지 않는다.

다음 확인 항목:

- 무료 CSV의 전체/샘플 구분, 행 수, 재료명·분량·원문 링크 컬럼.
- 조리 단계·이미지 포함 여부.
- 원본 저장, 정규화, 서비스 노출, 이미지 이용, 백엔드 사본 제공 권한.
- 비영리 또는 변경금지 조건이 있으면 이번 구조와 양립 가능한지 공급자 확인.

조리 단계가 없는 파일은 **검색용 카탈로그 후보**로만 취급한다. 현재 Recipe 스키마는 steps가 필수이므로 불완전 레코드를 정상 레시피로 넣지 않는다. 원문 링크 안내용 별도 계약은 백엔드·프론트와 합의가 필요하다. `원문 참고` 같은 가짜 단계나 LLM 조리법을 외부 원본인 것처럼 채우지 않는다.

공식 제휴 소개서에는 대규모 API 연동·콘텐츠 공급이 안내되어 있다. 이는 무료 무제한 API가 있다는 뜻이 아니며 별도 조건 확인이 필요하다. 문의·구매·계약 신청은 하지 않았다.

## 3. 확장 우선순위

식품안전나라 파싱 보완 → 농식품 공공데이터 결합 → KADX 무료 파일·권한 확인 순이다. TheMealDB는 개발용 보조 후보, Tavily는 부족할 때 원문을 찾는 최후 검색 경로로 유지한다. 검색 성공은 검색된 글 전문 복제·이미지 저장 허가가 아니다.

다른 사이트·공개 저장소·Kaggle 등에 대량 CSV가 있어도 최초 원천 권한과 조리 단계 유무 확인 전에는 반입하지 않는다. 사용자 제보·직접 작성 레시피도 동의·검토 정책을 먼저 정한다.

요리 이름만으로 원천 간 중복을 삭제하지 않는다. 같은 김치찌개라도 재료·분량·조리법이 다를 수 있다. `(source, sourceRecipeId)`를 유지하고 콘텐츠 중복과 메뉴 다양성을 별도로 측정한다. 규모 보고에서는 원본 수 / 구조 검증 수 / 권한 확인 수 / 서로 다른 메뉴 수를 구분한다.

## 4. 추가 확인한 공공 원천과 Tavily 연결

[한식진흥원 한식 정밀레시피(밥류)](https://www.data.go.kr/data/15142529/fileData.do)는 공식 목록에 밥류 30개, HWPX, 무료, 공공누리 제1유형(출처표시)으로 안내된다. 파일 본문을 아직 내려받아 정규화하지 않았으므로 추가 확보 레시피 수에 합산하지 않는다. 원본을 확보한 뒤 재료·분량·단계 순서를 확인하고 출처를 함께 보존하는 소규모 확장 후보이다.

농사로의 '향토음식 한영대역사전' 목록에는 공공누리 제3유형(변경금지)이 표시되어 있다. 이름이 비슷하다고 일반 향토음식 레시피 API와 같은 데이터로 간주하거나 농사로 전체에 같은 조건을 적용하지 않는다. 해당 자료를 정규화·재제공해도 되는지 확인하기 전 반입하지 않는다.

Tavily 실제 기본 검색 1회(약 4.362초)로 원천 후보 URL 5개를 확인했다. 로컬 결과는 `results/recipe_source_discovery_20261023.json`이며 검색 결과는 모두 PENDING_SOURCE_AND_USAGE_REVIEW다. 원문 수집·레시피 DB 반입은 0건이다. [공식 비용 문서](https://docs.tavily.com/documentation/api-credits)에 따르면 basic 검색은 요청당 1크레딧이다. 계정의 무료 잔여량은 별도 확인 대상이다.

현실적인 다음 순서는 한식진흥원 파일 구조 확인 → 농식품 3개 API의 전체 조회 키·최신 이용 조건 확인 → KADX 무료 파일의 실제 컬럼·이용 조건 확인이다. 원천 증가와 파서 통과 증가를 구분하며, 현재 구조 검증 통과 수는 여전히 870건이다.

### 상세 품질 확인

- TheMealDB에서 숫자+시간 단위 표현이 있는 레시피는 697건, 계량스푼 표현이 있는 레시피는 658건이다. 재료는 있지만 대응 계량이 빈 항목은 30개다. 시간 존재는 모든 조리 단계의 시간이 충분하다는 뜻이 아니며, 계량스푼 존재도 모든 조미료의 분량을 보장하지 않는다. 기준 인분을 구조화해 주지 않는 경우 임의로 1인분으로 정하지 않는다.
- TheMealDB의 `?` 또는 대체문자가 포함된 레코드는 3개다. 문장부호일 수도 있으므로 모두 손상 데이터라고 단정하지 않고 문맥 검토 대상으로 표시한다.
- 정밀레시피 중 '회덮밥' 문서에는 숫자+분 표현이 없었다. 비가열 요리 여부 등 문맥을 확인해야 하며 시간 미표기만으로 불량이라고 판정하지 않는다.
- 정밀레시피 '새싹비빔밥'의 재료표에는 물 640g, 밥 짓기 단계에는 875g이 있다. '흰밥'의 멥쌀 450g 행에는 lb 열 9.92가 함께 있다. 원문도 내부 불일치가 있어 그대로 추천 확정본으로 만들면 안 된다. 원문값을 추측 수정하거나 전체 환산 열을 신뢰하지 않는다.
- 아카이브 포털 표기 7,796행과 이번에 실제 내려온 2,033행이 일치하지 않는다. 행 수를 맞추기 위해 레코드를 생성하거나 레시피 수로 오인하지 않는다.

기존 식품안전나라 구조 검증본 870건에 최소 완전성 필터를 추가했다. 손상/미해결 문자 포함 22건, UNKNOWN으로 남은 미해석 분량 포함 129건, 가열 동작은 있으나 숫자 조리 시간 없는 500건을 검토 대상으로 분리했다. 사유는 중복될 수 있어 더해서 제외 수로 세지 않는다. 556건을 보류하고 314건만 반영했다. 이는 완전성 검사이지 314건 전체의 의미 정확도를 정답 라벨로 검증한 결과는 아니다. 보류본·원본은 삭제하지 않았다.

신규 문서는 재료표와 조리문을 직접 대조한 '김치볶음밥', '누룽지', '프랑스식 양파 수프' 3건만 추가했다. 예를 들어 김치볶음밥의 기름 84g은 조리 중 48g+36g으로 나뉘는 것을 확인했다. 나머지 한식 문서 28건과 TheMealDB 789건은 검토 보류 상태다. TheMealDB 까르보나라의 재료표 320g·달걀노른자 6개와 본문의 면 350g·달걀 3개가 다른 사례, 김프르의 감자 굽기 과정 누락, 연어 데리야키의 글레이즈 재료 누락 등은 추측 복원하지 않는다.

가공 범위:

- 한식 문서의 g 재료표, 준비·조리·담기 표의 내용 열과 원문 조언을 순서대로 보존했다. 불 세기 정의도 함께 남겼으며 잘못된 lb 환산 열은 사용하지 않는다. 기준 인분은 명시된 4인분이다.
- 큰술·작은술·가열 시간·온도는 원문에 있는 그대로 남긴다. 없는 값은 생성하지 않는다. 출처와 기구 안내는 첫 실제 단계의 주석으로 합쳐 독립된 가짜 조리 단계로 세지 않는다.
- 양파 수프는 검토한 재료 10개 이름만 명시적 번역표로 한국어화했다. 조리법은 영어 원문이며 분량 원문도 보존한다. kg→g, L→ml만 환산하고 tbs·tsp·sliced는 임의 g/EA 환산 없이 UNKNOWN과 원문 분량으로 남겼다. 인분은 원천 미제공이라 null이다.
- KADX·아카이브처럼 비상업·변경금지 조건이 있는 자료와 API 키 없는 신규 공급자·공개 샘플만 있는 공급자는 반입하지 않았다. TheMealDB 1건은 dev 전용이며 stage·prod 이전 승인으로 해석하지 않는다.

반영 전 dev DB를 PostgreSQL custom dump로 백업했다. 백업은 dev 호스트의 `/var/lib/pgsql/recipe-backups/pre-recipe-20261023.dump`에 postgres 전용 0600 권한으로 보관하며 개인 데이터가 있으므로 Git·로컬 보고서로 복사하지 않는다. 반입 파일은 원천별 체크섬으로 전송을 확인하고, 트랜잭션·기존 스냅샷 일치 검증·동일 쓰기 락으로 적용했다. 기존 사용자 분석·피드백·소비기한 테이블의 데이터는 수정하지 않았다. 같은 연결에서 기존 소비기한 규칙 전체 62건을 전후 확인했다.
