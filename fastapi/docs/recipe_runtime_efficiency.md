# 레시피 추론 설정과 웹 추출 효율

공유 Worker의 프롬프트 계약은 `recipe-grounded-v10`이다. 공개 추천 요청 / 결과 / 콜백 JSON은 변경하지 않는다. FastAPI와Worker는 함께 배포한다. 이번 변경 자체에는 SQL이 없다.

## 동일 모델의 context 통일

- Worker `OLLAMA_NUM_CTX` 기본32768, 허용8192~32768.
- start.sh는 OLLAMA_NUM_CTX → 기존 OLLAMA_CONTEXT_LENGTH → 기본32768 순서로 값을 고르고, Ollama 서버의 OLLAMA_CONTEXT_LENGTH도 같은 값으로 맞춘다.
- 레시피 / OCR 텍스트 상품분류 / 실물 이미지 상품분류 요청의 num_ctx를 모두 동일 설정으로 보낸다.
- 기존 자동 기본32K로 준비했다가 레시피16K 요청 때문에 실행기를 다시 생성하는 경로를 줄인다. VRAM을 보고 운영자가 줄일 때도 모든 경로를 함께 바꾼다.
- 워밍업은 빈 프롬프트 로딩에서 끝내지 않고, 같은 context에서 실제 토큰 하나를 생성한다. 최종 body의 done / eval_count도 확인한 뒤에만 완료를 선언한다.
- WARM_MODEL_ON_START=false이면 운영자가 워밍업을 생략한 것이다. 로딩 / 모든 크기의 CUDA 그래프가 언제나 캐시돼 있다는 보장은 아니다.

사진 분석의 결과 계약 / OCR 모델 / Gemma 모델은 유지한다. 공유 모델의 context 설정은 사진 경로에도 적용된다. 이번 기본32K는 이전 운영 워밍업과 사진 경로의 실측 자동32K를 보존하는 선택이다.

## 조리문 복사 대신 원문 행 선택

기존 EXTRACT는 재료 / 분량과 긴 조리문 전체를 모델이 다시 출력했다. 이제 내부 모델 출력은 title / ingredients(name, quote) / stepRanges(firstLine, lastLine) / status다. 서버가 선택한 행의 원문을 줄바꿈까지 그대로 복원해 기존 ExtractedRecipe.steps로 반환한다.

- 원문 순서 / 비중복 / 행 범위를 검증한다. 잘못된 번호를 임의 수정하거나 누락한 문장을 생성하지 않는다.
- 재료 인용 / 분량은 기존 원문 검증을 거친다. 시간 / 불 조절 / 마무리 문장은 연속 행으로 포함하고, 번호 조리에 이어지는 문단을 빠뜨리면 FastAPI가 거부한다.
- 광고나 후기와 섞인 본문을 무조건 수용하지 않는다. 혼합 배합은 기존 MIXED_BATCH로 유지한다.
- 원문24KB / 최대2000행을 넘으면 자르지 않고 거부한다.
- 내부 EXTRACT 출력 토큰 상한은2048에서1536으로 낮춘다. 조리문 전체를 다시 생성하지 않아 실제 출력량을 줄이는 것이 목적이며 상한 자체가 속도 향상을 증명하지 않는다. length 종료는 계속 실패로 처리한다.
- 공개 API에는 stepRanges가 노출되지 않는다. 내부 Worker 결과 역시 기존 steps를 반환한다.

## 시간 예산과 취소

FastAPI 원격 어댑터는 주소 탐색에 사용한 시간을 뺀 뒤, 기본2초의 전송 / 응답 여유를 제외한 예산만 Worker에 보낸다. 설정은 `RECIPE_WORKER_TRANSPORT_MARGIN_SECONDS`, 허용0.1~5초다. 소진된 예산으로는 새 모델 호출을 시작하지 않는다. 호출자의 context dict는 변경하지 않는다.

원천 처리기는 남은 시간이 최소 모델3초 + 전송 여유보다 짧으면 SOURCE_BUDGET_EXHAUSTED로 보류한다. 이 보류를 원문 오류로 캐시하지 않는다. 3초는 최소 시작 기준일 뿐 실제 완료를 보증하지 않는다. 기본 전체 웹 보충8초 / RANK20초 / 전체 추천45초 상한은 늘리지 않았다.

원문 지문 / 모델 / 프롬프트 / 파서 버전별 성공 캐시와 같은 원문의 진행 중 작업 병합을 유지한다. 파서 버전은 recipe-source-v2다. 취소된 마지막 대기자는 원격 작업을 취소하지만 HTTP 취소가 Ollama GPU 작업의 즉시 정리를 보장하지는 않는다. 이번 변경은 짧은 예산으로 긴 출력 작업을 시작하는 빈도를 줄이는 방식이며, 확인되지 않은 sleep / 비공식 slots API로 서비스 잠금을 추가하지 않는다.

v10으로 버전이 바뀌면 이전 모델 판단 / 원천 맛 프로필 캐시는 재사용하지 않는다. 기존 맛 프로필 기능을 사용하는 운영자는 사전 평가도 현재 계약으로 수행한다. 스키마 변경은 없다.

## 검증 범위

원문 여러 줄 / 찌는 시간 / 양념 분량 보존, 잘못된 범위 / 중복 / 역순 거부, 예산 소진 시 무호출, 재사용 / 공유 작업 취소를 검증한다. 실제 RunPod 재시험을 시도했으나 예약 종료 후 컨테이너에 접근하지 못했다. 실제 지연 개선량이나 웹 추출 성공률 향상을 확정한 상태는 아니다. 다음 배포 후 같은 원문과 새 요청으로 기존 상세 로그를 비교한다.
